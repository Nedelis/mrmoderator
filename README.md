# Мистер Модератор

Чат-бот и мини-приложение в **MAX** для старост и актива студенческих групп: напоминания, задания, долги, экзамены и учебные материалы группы в одном месте, а уведомления доставляет бот — лично каждому, мимо флуда общего чата.

Трек хакатона — «Образовательные решения».

## Назначение

Староста тратит 1,5–2 часа в день на то, чтобы донести информацию до группы: пересылает объявления, напоминает о дедлайнах, держит в голове, у кого какие долги. Важное тонет во флуде группового чата, а если староста на день выпал — группа остаётся без информации.

«Мистер Модератор» забирает эту рутину:

- **Группа за одну команду.** Староста создаёт группу в боте, одногруппники вступают по ссылке-приглашению.
- **Напоминалки, задания, экзамены.** Создаются в мини-приложении; кнопка «Напомнить всем» — и бот пишет каждому участнику лично.
- **Долги под контролем.** Реестр задолженностей группы у старосты, личная статистика у студента, ежедневные напоминания должникам и утренняя сводка старосте.
- **Материалы.** Ссылки на конспекты и материалы к экзаменам в одном разделе.
- **Роли.** Староста, замстаросты, профорг, студент — часть работы можно делегировать.

Исследование проблемы, гипотезы и метрики — [docs/research.md](docs/research.md).

## Основной пользовательский сценарий

1. Староста открывает бота → `/creategroup ИС-21` → получает код и ссылку-приглашение (`/invite`).
2. Одногруппники вступают по ссылке или командой `/join КОД`.
3. Староста открывает мини-приложение (`/open` или кнопка «🔗 Открыть приложение»), создаёт групповую напоминалку и нажимает «Напомнить всем».
4. Каждый участник получает личное сообщение от бота; долги и дедлайны видны на дашборде старосты.
5. Планировщик каждое утро присылает старосте сводку, а должникам — напоминания.

Пошаговый сценарий с ожидаемым результатом — [docs/demo-script.md](docs/demo-script.md).

## Состав и архитектура

```
MAX (чат + мини-приложение)
        │ HTTPS (туннель)
        ▼
  web  — nginx: React SPA + прокси /api ──► api — FastAPI ──┐
                                                            ├──► SQLite (volume)
  bot  — maxapi, long polling  ◄──► MAX Bot API ◄── scheduler — APScheduler
```

| Сервис | Что делает | Технологии |
|---|---|---|
| `web` | Мини-приложение; nginx раздаёт статику и проксирует `/api` в `api` | React 19, TypeScript, Vite 8, nginx |
| `api` | REST API мини-приложения, авторизация по initData MAX, права по ролям; при старте применяет миграции и (при `USE_TEST_DATA=true`) очищает БД и наполняет её тестовыми данными | Python 3.12, FastAPI, SQLAlchemy 2, Alembic |
| `bot` | Команды бота: группы, приглашения, ссылка на мини-приложение | maxapi |
| `scheduler` | Уведомления о дедлайнах, долгах, утренняя сводка | APScheduler |

Подробно — [docs/architecture.md](docs/architecture.md). API — [docs/api.md](docs/api.md) и [docs/openapi.yaml](docs/openapi.yaml) (OpenAPI 3.1).

## Быстрый старт

Нужны Docker с Compose v2 и токен бота MAX.

```bash
cp .env.example .env
```

Вписать в `.env` токен: `MAX_BOT_TOKEN=...`. Затем — **одна команда для запуска всех компонентов**:

```bash
docker compose up -d --build
```

Через ~20 секунд:

- мини-приложение — http://localhost:8080
- API и Swagger UI — http://localhost:8080/api/docs
- бот отвечает в MAX

Сборка с нуля занимает меньше минуты (без учёта скачивания базовых образов).

### Публичный доступ для MAX

MAX открывает мини-приложение только по HTTPS. Все компоненты доступны через один порт `web` (8080), поэтому хватает одного туннеля:

```bash
clo publish http 8080
```

1. Скопировать выданный `https://…` адрес в раздел [«Публичные адреса»](#публичные-адреса).
2. На платформе MAX для партнёров указать этот адрес как URL мини-приложения бота.
3. В `.env` поставить `STRICT_AUTH=true` и перезапустить API: `docker compose up -d api` — теперь каждый пользователь MAX работает со своей группой.

## Переменные окружения

Файл `.env` в корне (шаблон — [.env.example](.env.example), рабочих секретов в нём нет).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `MAX_BOT_TOKEN` | — | Токен бота MAX. **Обязателен** для `bot` и `scheduler`; без него API работает, но не отправляет уведомления |
| `MAX_BOT_USERNAME` | `t595_hakaton_max_bot` | Ник бота без `@` — для ссылок на мини-приложение и приглашений |
| `STRICT_AUTH` | `false` | `true` — проверка подписи initData MAX в каждом запросе; `false` — демо-режим: все запросы от тестового старосты |
| `USE_TEST_DATA` | `false` | `true` — при старте `api` **очищает БД** и наполняет её тестовыми данными из `seed/test_data.json` |
| `DEBUG` | `false` | Логирование SQL-запросов |
| `DATABASE_URL` | в Docker: `sqlite+aiosqlite:////app/data/mrmod.db` | Строка подключения. В Docker задаётся в `docker-compose.yml`; значение из `.env` используется при запуске без Docker. Поддерживается `postgresql+asyncpg://…` |
| `WEB_PORT` | `8080` | Порт мини-приложения на хосте |
| `API_PORT` | `8000` | Порт API на хосте |
| `VITE_API_BASE` | `/api` | Базовый путь API во фронтенде (подставляется при сборке образа `web`) |
| `VITE_USE_API_MOCK` | `false` | `true` — фронтенд работает на встроенных моках без бэкенда (при сборке) |
| `CORS_ORIGINS` | localhost:5173, 3000, 8080 | JSON-массив разрешённых origin. Нужен, только если фронтенд и API на разных доменах |
| `MAX_FILE_SIZE` | `20971520` | Зарезервировано (лимит размера файла для загрузки) |

## Работа с данными

- Все данные хранятся в SQLite-файле `/app/data/mrmod.db` в Docker volume `sqlite_data` и переживают перезапуск контейнеров.
- **Исключение:** при `USE_TEST_DATA=true` БД **очищается при каждом старте `api`** и наполняется тестовыми данными.
- Схема создаётся и обновляется миграциями Alembic при каждом старте `api` (`alembic upgrade head`).
- О пользователе хранятся только данные из MAX: id, имя, фамилия, username, ссылка на фото — плюс группа и роль. Телефоны и почты студентов не собираются.
- Доступ к данным ограничен группой пользователя: объекты других групп недоступны (`404`), действия — по правам роли (`403`).
- Токен бота хранится только в `.env`, который не попадает в git и Docker-образы (`.dockerignore`).
- Переход на PostgreSQL — поменять `DATABASE_URL` в `docker-compose.yml` на `postgresql+asyncpg://…`.

## Тестовые данные

- **Демо-режим** (`STRICT_AUTH=false`, по умолчанию). При первом запросе к API автоматически создаются группа `TEST-GROUP-01` «Тестовая группа» (код приглашения `TESTINVITE`) и пользователь «Тест Тестов» с ролью **староста**. Все запросы мини-приложения и API выполняются от его имени — логин и пароль не нужны. Данные группы (напоминалки, долги и т.д.) создаются в ходе проверки.
- **Наполнение БД тестовыми данными** (`USE_TEST_DATA=true`). При старте `api`:
  - применяются миграции Alembic;
  - **все данные в БД удаляются** (включая `TEST-GROUP-01`, если была);
  - из `backend/seed/test_data.json` загружаются данные: группа `iu7-42b` «ИУ7-42Б» (код приглашения `IU7TEST`), 12 пользователей (староста, замстаросты, профорг, 9 студентов), 8 напоминаний, 6 долгов, 8 заданий, 7 материалов, 6 экзаменов, 4 материала к экзаменам, 6 писем, 4 почтовых ящика, настройки группы.
  - ⚠️ **Данные не сохраняются между перезапусками.** Каждый рестарт `api` с `USE_TEST_DATA=true` — БД заново очищается и наполняется.
  - Перезалить вручную: `docker compose exec api python -m seed.seed --force`.
- **Режим с MAX** (`STRICT_AUTH=true`). Тестовые учётные записи — любые аккаунты MAX: первый создаёт группу `/creategroup` и становится старостой, остальные вступают по `/join КОД`.
- **Фронтенд без бэкенда.** Сборка с `VITE_USE_API_MOCK=true` показывает интерфейс на встроенных моковых данных ([web/src/api/mock.ts](web/src/api/mock.ts)) — они смоделированы и нигде не сохраняются.
- **Сбросить данные:** `docker compose down -v` (удаляет volume с базой).

## Известные ограничения

- **Почта — заглушка.** Ящики сохраняются, но синхронизации с почтовыми серверами и пересылки писем нет: `/api/mail/refresh`, `/configure`, `/{id}/forward` отвечают успехом без реального действия. Список писем пуст, пока его не заполнить в БД.
- **Демо-режим — один пользователь.** При `STRICT_AUTH=false` все, кто открывает мини-приложение, работают от имени одного тестового старосты и не связаны с группами, созданными в боте. Для реального сценария нужен `STRICT_AUTH=true`.
- **initData действует 1 час.** Если мини-приложение открыто дольше, запросы начнут получать `401` — нужно открыть приложение заново.
- **Материалы — только ссылками.** Загрузки файлов на сервер нет: материал добавляется ссылкой (файлы остаются в MAX или облаке).
- **Удаление экзаменов** в интерфейсе пока не реализовано.
- **Групповой чат.** `/setchat` сохраняет чат группы, но уведомления пока отправляются только личными сообщениями участникам.
- **Настройки уведомлений** (`/api/settings`) зарезервированы и отвечают `403`.
- **SQLite** рассчитан на один экземпляр `api`; для горизонтального масштабирования — PostgreSQL.
- **`USE_TEST_DATA=true` стирает БД при каждом рестарте.** Не используйте на реальных данных.
- Автотестов нет; ESLint выдаёт замечания по правилам хуков React (`set-state-in-effect`, `exhaustive-deps`) — на работу не влияют.

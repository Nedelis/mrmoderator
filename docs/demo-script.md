# Сценарий демонстрации и проверки

Документ для двух случаев: **проверка** решения экспертом (пошагово, с ожидаемым результатом) и **демонстрация** на защите (что показывать и что говорить).

Публичные адреса и ссылка на бота — в [README](../README.md#публичные-адреса).

---

## Основной пользовательский сценарий

> Староста создаёт группу в боте, приглашает одногруппников, ставит групповую напоминалку и долг — бот сам доставляет уведомления нужным людям в MAX, а староста видит картину по группе в мини-приложении.

Нужны два аккаунта MAX: **А** — староста, **Б** — одногруппник. На сервере — `STRICT_AUTH=true` (каждый пользователь видит свою группу).

### 1. Староста создаёт группу (чат с ботом, аккаунт А)

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1.1 | Открыть бота по ссылке из README, нажать «Начать» / отправить `/start` | Приветствие, список команд, кнопки «➕ Создать группу» и «🚪 Вступить по коду» |
| 1.2 | Отправить `/creategroup ИС-21` | «✅ Группа «ИС-21» создана! Ты — староста», код приглашения |
| 1.3 | Отправить `/invite` | Ссылка-приглашение `https://max.ru/<бот>?start=invite_<КОД>` и код |
| 1.4 | *(необязательно)* Создать групповой чат, добавить бота, отправить в нём `/setchat` | «✅ Чат привязан к группе» |

### 2. Одногруппник вступает (аккаунт Б)

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 2.1 | Перейти по ссылке-приглашению **или** открыть бота и отправить `/join <КОД>` | «✅ Ты вступил в группу «ИС-21»» |
| 2.2 | Неверный код: `/join AAAA` | «❌ Неверный код приглашения.» |

### 3. Староста работает в мини-приложении (аккаунт А)

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 3.1 | В боте нажать «🔗 Открыть приложение» или отправить `/open` | Открывается мини-приложение, в профиле — «Староста · ИС-21». Меню: Дашборд, Личная статистика, Напоминания, Материалы, Почта, Роли |
| 3.2 | «Напоминания» → блок «➕ Создать»: тип «Напоминание», название «Сдать реферат», дата — завтра, время, «Для всей группы» → «➕ Создать напоминание» | Карточка появляется в списке и на Дашборде |
| 3.3 | На карточке нажать «🔔» («Отправить напоминание») | Всплывает «Разослано N участникам». Аккаунт Б получает в чате с ботом «🔔 Напоминание: Сдать реферат…» |
| 3.4 | «➕ Создать» → тип «Долг»: участник Б, предмет, тип «Экзамен», дата в прошлом | Долг появляется в списке и в блоке «Долги группы» на Дашборде |
| 3.5 | «Роли» → «Назначить роль»: участник Б, роль «Замстаросты» → «✅ Назначить роль» | Роль Б меняется в списке участников |
| 3.6 | Создать напоминание без названия | Форма не отправляется, под полем — «Введите название» |

### 4. Одногруппник видит результат (аккаунт Б)

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 4.1 | Открыть мини-приложение | Группа «ИС-21», роль по шагу 3.5; видна групповая напоминалка |
| 4.2 | «Личная статистика» | Долг из шага 3.4 со статусом «Просрочен» |
| 4.3 | Отметить напоминалку выполненной | Отметка сохраняется после перезагрузки |

### 5. Автоматические уведомления (планировщик)

| Когда | Что придёт |
|---|---|
| Ежедневно в 08:00 МСК | Старосте А — «☀️ Доброе утро… Сводка по группе»: сколько долгов, сколько просрочено, дедлайны на сегодня |
| Ежедневно в 09:00 МСК | Должнику Б — «🚨 Просроченный долг!» (не чаще раза в сутки) |
| На вехах 7д / 3д / 1д / 8ч / 2ч до дедлайна (проверка каждые 15 минут) | Всем участникам — напоминание о групповой напоминалке или задании; должнику — о долге |

Чтобы не ждать расписания, задачи можно запустить вручную:

```bash
docker compose exec scheduler python -c "import asyncio; from app.scheduler import jobs; asyncio.run(jobs.send_daily_summary())"
```

```bash
docker compose exec scheduler python -c "import asyncio; from app.scheduler import jobs; asyncio.run(jobs.check_overdue_debts())"
```

## Быстрая проверка без MAX (демо-режим)

При `STRICT_AUTH=false` мини-приложение открывается в обычном браузере от имени тестового старосты. Есть два режима.

**С тестовыми данными (`USE_TEST_DATA=true`).** При старте `api` БД очищается и наполняется из `seed/test_data.json`: группа `iu7-42b` «ИУ7-42Б», 12 студентов, 8 напоминаний, 6 долгов, 8 заданий, 7 материалов, 6 экзаменов, 6 писем.

1. В `.env` выставить `USE_TEST_DATA=true`, `STRICT_AUTH=false`.
2. `docker compose up -d --build`.
3. Открыть http://localhost:8080 — Дашборд «ИУ7-42Б» с напоминаниями и долгами.
4. API — http://localhost:8080/api/docs, примеры запросов — в [api.md](api.md#примеры).
5. Уведомления в MAX не уходят: у тестовых пользователей фейковые `max_user_id` (`sentTo: 0`). Для реальной доставки нужен `STRICT_AUTH=true` и аккаунты MAX.

**Без тестовых данных (`USE_TEST_DATA=false`, значение по умолчанию в `.env.example`).** Создаётся «Тест Тестов» в группе `TEST-GROUP-01`, данные вводятся вручную через интерфейс.

## Демонстрация на защите (≈ 3 минуты)

| Время | Что показываем | Что говорим |
|---|---|---|
| 0:00 | Слайд с проблемой | Староста тратит 1,5–2 часа в день на пересылку информации и напоминания; 100% опрошенного актива пропускали важное |
| 0:20 | Бот: `/creategroup`, ссылка-приглашение | Группа создаётся за одну команду, одногруппники вступают по ссылке — без регистрации и отдельного приложения |
| 0:50 | Мини-приложение: создать групповую напоминалку → «Напомнить всем» | Одно действие вместо рассылки в личку каждому |
| 1:20 | Телефон одногруппника: пришло сообщение от бота | Уведомление в личке не тонет в флуде группового чата |
| 1:40 | Долг участнику → Дашборд старосты | Задолженности группы видны целиком, а не держатся в голове |
| 2:10 | Утренняя сводка старосте (запуск задачи вручную) | Бот сам напоминает должникам и присылает старосте сводку |
| 2:30 | Роли | Часть работы можно делегировать заму и профоргу |
| 2:45 | Слайд с эффектом и масштабированием | Метрики пилота и следующие шаги |
